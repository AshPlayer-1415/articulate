# Security reporting

Never put credentials, consent URLs, private transcripts, user profiles or
exploitable details in a public issue. If GitHub's private vulnerability reporting
is enabled, use this repository's Security tab to report privately. Before that
feature is enabled, contact the maintainer privately through an existing trusted
channel; do not post sensitive details merely to ask for a channel.

The maintainer must enable and verify private reporting before announcing the
public pilot. A SECURITY.md file does not enable GitHub's reporting feature.
No response-time guarantee or independent security certification is claimed.

Local consent and adversarial tests cover specific invariants, not universal
injection immunity or the behavior of other filesystem tools in your AI host.
Keep Node and AI hosts patched. Revoke an affected client's sharing while a
suspected disclosure is investigated. Original host histories and provider data
are outside Articulate's erasure scope.
